# 字幕合同

> 字幕要求的唯一所有者。**本合同要求不可变更。** 渲染永远走官方 captions（`captions.mjs` + caption skin + 官方运行时）；本仓最多只补充「分组数据」，不重写渲染。

## 要求（不可变更）

1. **来源**：字幕文本必须直接读取锁定口播稿原文，逐字一致。禁止从词级时间 token 流拼接生成字幕文本；词级时间只用于确定显示时间与高亮进度。
2. **切分**：切分单位 = 锁定稿相邻标点之间的语块（`。！？，、；：` 为边界，收尾引号/括号归该行行尾）；语块 ≤22 字整体成行；前后有标点的 1–2 字语块允许独立成行；超长无标点语块允许中点均衡切分（不拆英文词）并登记 `balancedSplit`。
3. **标点纪律**：每条以终止它的原始标点结尾；不得以标点开端；禁止添加任何标点；禁止按字数硬切。
4. **呈现**：单行显示；无动效（只允许当前行颜色高亮）；固定底部字幕区；画面已呈现的内容不再带入字幕。
5. **时间**：行时间从词级时间轴直取（LCS 对齐，容忍 TTS 折叠差异），不按句内比例估算。

## 实现路线（官方优先）

1. **第一步**：官方 `captions.mjs build` 原生输出，主智能体对照本合同逐条实测（第一支视频验证）。
2. **第二步**：仅当原生不满足（标点切分/单行/逐字任一不达标）时，harness 按本合同算法从「锁稿 + 词级时间」生成分组数据，走官方 caption 数据通道（caption-overrides 等官方入口）注入；**渲染器仍是官方**。
3. 机器合同：只要生成了分组数据，就用本仓脚本确定性复算并与在盘数据逐行比对，不一致即阻断；分组数据只能由本仓脚本产出。

## 与官方 captions 的关系

- 官方 karaoke 高亮 = 本合同「仅当前行高亮」的官方实现。
- 官方 caption skin（Step 2 随 preset 生成）承载样式；本合同只约束「文本、切分、单行、无动效」。
- 官方已知误报（caption 词的 `text_box_overflow` 1–4px）按官方 SKILL 规定不追。
