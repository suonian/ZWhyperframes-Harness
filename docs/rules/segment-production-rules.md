# 锁定稿与分段规则

## 输入与锁定

- 用户输入可以是完整资料包（锁定口播、说明、参考材料、图片、视频）。完整输入原样归档；只有明确标记的锁定口播进入 TTS 与生产。
- 锁定稿是内容真源：每段 `user_script.txt` 是其冻结片段，整份与段级 SHA-256 绑定；生产期间不修改、不润色、不回写锁定正文。
- 段文本任何改动 → 该段必须重跑 TTS（铁律：禁止只刷哈希）。

## 分段

- 长稿按完整语义、论证关系和自然转折分段，不按字数或帧数截断。普通段落目标 60–90 秒，真实语音硬上限 120 秒，接近上限在自然转折处切分。
- 分段计划锁定全文、每段正文与范围的 SHA-256；脚手架只接受已锁定计划，且不得覆盖已进入生产的段落。
- 每段 = 一个 HF 项目（官方 `init --skill=faceless-explainer`），段内 Frame 划分遵循官方 Step 3 的叙事/视觉职责切分（语音 >8s 或 >4 Scene 是主智能体重查自然切点的信号，不是硬门禁）。

## 生命周期

- 段脚手架 ≠ 开始授权。每段（含第 1 段）必须先有用户「开始授权」才能进入正式生产。
- 段间交接只发生在下一段（或 master）的开始授权中；前一段必须有正式 MP4 且完成渲染后复查。
