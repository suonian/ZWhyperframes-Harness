# Changelog

This project records notable changes in its releases.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/lang/en/).

> ⚠️ **HyperFrames version pinning**: `0.8.36`. Upgrading is not a version-number change but a **contract audit** task — official skill content changes with upstream commits, and the rules in this repository quote it verbatim.

> The files under `docs/rules/` referenced below are maintained in **Chinese only**; Chinese is authoritative for their normative requirements.

## [0.2.10] — 2026-11-01

**A1 integration branch**: `v0.2.9` (`53c456c`) as the trunk, absorbing the Windows platform fixes, visual-baseline gates, output-quality gates and the full test suite from `feat/visual-baseline-and-windows-hardening`, while keeping main's final-delivery contract, the frame tools (`frame-guard` / `css-selector-audit`) and the `creative-mode-zh` preset. **Default visual baseline = official `capsule` + `Noto Sans SC`; `creative-mode-zh` becomes an explicitly-selectable optional preset (no longer mandatory).** Exactly one default policy is allowed — every "must use creative-mode-zh" statement is withdrawn as of this release.

### Distribution and size (460KB safety line)

- Integration build, measured: **48 files / 405.1KB of file bytes / 421.6KB request body** (self-imposed 460KB safety line, 38.4KB headroom). The publish gate **constant is unchanged** (still the server-measured 476KB hard limit — that is a fact); what was cut down is the content, not the bar.
- **`package-lock.json` is no longer shipped (-93.9KB)**: it is the only large file a consumer can run without — `bootstrap.sh` uses `npm install` (not `npm ci`), the CLI version is pinned exactly to `0.8.36` in `package.json`, and the official skill helper dependencies are pinned one by one at bootstrap time by `scripts/lib/official-deps.mjs`. The repository and CI keep and use the lock (`npm ci` + reproducible builds).
- **Why not the "FAQ out + preset repo-only" pair**: doing both still lands at a **479KB request body — still over the 460KB line** (measured: 508,587 → 462,379 file bytes plus ~17KB of request-body overhead). Cutting further would have to touch `docs/rules/` — the product's skeleton. Dropping the lock instead satisfies 460KB while keeping the FAQ, the `creative-mode-zh` preset and every rules document: the least damaging cut under the size constraint, and it does **not** touch the gate constant.
- `frame-guard.mjs` / `css-selector-audit.mjs` stay repo-only (development-time pre-screening tools; not shipped, not wired into `gate preflight`).

### Changed
- **Template / palette / voice baseline landed (using the official set, not inventing one)**: this round started with an **official asset inventory** before touching anything — confirming that HyperFrames **ships** 13 frame presets (`hyperframes-creative/frame-presets/`, each with a `FRAME.md`, a showcase and a caption skin), ships brand remixing (`build-frame.mjs --tokens`, mapping by role), ships recipe freezing (`recipe.mjs freeze/use` → `~/.media/recipes/`) and preference memory (`prefs.mjs`). The user's own set **does exist**, and comparing it showed it is exactly a **CJK remix of the official `capsule` preset** (all 13 color keys byte-identical, only the fonts swapped from Bodoni Moda + Space Grotesk to Noto Sans SC) — **not a separate system**. So this repo deliberately does **not** create a `brand/` palette copy (that would be a second source of truth that drifts across projects); it adds `docs/rules/visual-baseline.md` instead, which only declares "this project defaults to `capsule` + `Noto Sans SC`" and states plainly that this is a **preference, not an exclusion** — all 13 presets remain legal, an explicitly named preset is honoured, and the official `≥1.4cqw` floor plus the px-chrome clause that 13/13 official presets state are **not** contradicted; the project-level floor is only tightened to 28px.
- **New visual baseline gate `gate.mjs baseline`** (filled in only where official does not reach): the official `check` audits WCAG contrast and geometry, and **does not check palette ownership, the project-level type-size floor, or voice consistency**. The new gate judges four things — ① no frame color outside `frame.md`'s `colors:` declarations; ② carrying text ≥28px (official chrome tokens exempt); ③ `frame.md`'s own carrying px tokens ≥28px (baseline self-check); ④ the segment's TTS manifest `voice_profile` matches the source of truth. It is wired into the `preflight` chain.
- **The voice source of truth is now single**: the voice parameters lived only in `VOICE_PROFILE` inside `tools/minimax/scripts/minimax_tts.py`, with zero declaration in the rules layer and no way to verify them. The Python side now exposes a read-only `--dump-voice-profile`, and the gate **asks the source of truth** instead of copying the constant (a copy means two sources of truth, and changing one while forgetting the other lets the gate pass on a stale value). Python interpreter resolution moved up into `scripts/lib/python-runtime.mjs`, shared by TTS and the gate, so the two cannot drift.
- **Official skill dependencies and version are now pinned** (a real gap this round closed): the official `animation-map.mjs` carries **its own dependency resolution** — it needs `@hyperframes/producer` and `@hyperframes/core`, and neither is **inside** the hyperframes CLI package (measured: with only the CLI installed, `node_modules/@hyperframes` does not exist at all). Both of the official loader's fallbacks are unacceptable: when a package is missing it installs into a temp directory and deletes it afterwards (**every single animation-map run re-downloads ~100MB**); and when it cannot infer a version it **falls back to `@latest`** with a single stderr line — measured, upstream latest is already 0.8.223, 187 patch versions ahead of the locked one, and the drift is **silent**. Root cause: the official loader infers the version from a `package.json` named `hyperframes` / `@hyperframes/cli` found in its own directory's ancestor chain; this repo's package is named `zwhyperframes-harness`, so the inference always misses. Now pinned by the single source of truth `scripts/lib/official-deps.mjs`: `bootstrap.sh` installs the dependencies at the locked version into the **repository** `node_modules` (`--no-save --no-package-lock --ignore-scripts`: not written into `package.json`, lock file untouched, lifecycle scripts never executed — which is why puppeteer does not download a second Chromium; the browser is the `chrome-headless-shell` the official CLI already caches), with every transitive dependency pinned individually (producer declares `^0.8.36`; measured, `@hyperframes/engine` drifts to 0.8.223); `hf-env.sh` exports `HYPERFRAMES_SKILL_PKG_VERSION=0.8.36`, so the official loader has no `@latest` fallback left.
- **`gate animation-map --generate`**: when the artefact is missing, it first invokes the **official** script to generate it and then asserts the content (cwd pinned to the segment directory, absolute `--out` passed — which sidesteps the official "relative `--out` is resolved against cwd" trap). Previously, `gate animation-map` simply could not be satisfied on a clean clone following the documented flow.
- **The packaging and publishing size checks now use one and the same measure** (before, it was "packaging passes, publishing is bound to fail"): `build-skill-package.mjs` judged the **sum of file bytes** against a 470KB line, while `publish-skillhub.mjs` judged the **real multipart request body** against a 460KB line — and the request body is more than a dozen KB larger than the file sum (multipart headers + the changelog field + other fields), so a package could pass the build and still be unpublishable. Measured: with 47 files and a 451.2KB file sum, the real request body was 466.5KB — **last round's package did not fit the publish gate**. Now consolidated in `scripts/lib/package-limits.mjs`: the build judges the **estimated request body** (fail-closed, no oversized package is produced), the publish judges the **real body** and **reconciles it against the estimate** — a mismatch aborts the upload (if the estimator has drifted from the real construction, refuse rather than let through a package that "passes locally and explodes online"). This is exactly the 2026-10-24 audit finding M-21 ("a passing build does not mean publishable").
- **The publish gate moves from 460KB to 476KB (and now judges the "request body")**: the request body size is now computed **deterministically** — the build estimates it with the same algorithm, the publish checks the real body and reconciles the two (a mismatch aborts the upload). The goal of "never let the server disconnect silently" is now achieved by **refusing to produce the package in the first place**, so there is no longer a need for a line 15KB below the measured value. And since 475KB is **measured to pass**, any request body ≤475KB is provably safe — so the gate is set at the **measured server ceiling** of 476KB (leaving almost no hidden margin: any overflow makes the build fail-closed and say "content too large, please dispose of it", rather than being dropped halfway through an upload). The disposition order is fixed: **① widen the exclusion list → ② move long documents to the repository → ③ only then talk about raising the limit**. Steps ① and ② are done this round (the distribution-side toolchain, the MiniMax reference docs and the end-to-end walkthrough with its example inputs leave the package as groups, giving up roughly 46KB; the full FAQ and the distribution contract also moved to `docs/architecture/`), but the **visual baseline capability** (new rulebook + gate + judgment library, about 33KB) still exceeded 470KB after both steps, so the gate finally moves from 470KB to the measured ceiling of 476KB.
- **The changelog field now has a ceiling**: it is a **field** in the request body (not a file in the package), and its size is decided by the repository's `CHANGELOG.md` — at release time it becomes the whole section of the new version (this repo's current "unreleased" section is already around 30KB), so having no ceiling means the over-limit is discovered on launch day. It is now truncated to 8KB with an **explicit marker** (silently truncating would make people believe they are reading the whole thing).
- **The distribution-side toolchain leaves the distribution package as a group**: `build-skill-package.mjs` / `install-skill.sh` / `lib/changelog.mjs` / `lib/package-limits.mjs` — **consumers install the skill to get work done with the harness, not to repackage and republish it**; the packaged `package.json` correspondingly drops the npm scripts that point at them (previously only `publish-skill` was stripped).
- **The end-to-end walkthrough leaves the distribution package**: `references/walkthrough.md` and its example inputs are teaching material for "copy the whole flow once"; they are always available in the GitHub repository. What the package keeps is what **running and troubleshooting** needs: `references/faq.md` (symptom index), `references/commands.md` (command contract) and `docs/rules/` (normative contracts).
- **MiniMax's third-party API reference docs leave the distribution package**: `HF_AUDIO_SUBTITLE_FORMAT.md` / `VOICE_PROFILE.md` / the request sample — nothing reads them **at runtime** (the voice profile parameters are hardcoded in the script); they only serve maintainers.
- **Paths inside the repository are now always relative to the repository root**: native programs (node / git / npm) do not understand MSYS POSIX absolute paths on Windows, and a **login shell presets `MSYS_NO_PATHCONV=1`, which switches that conversion off** — so the same script works under `bash -c` and silently fails under `bash -lc`. A relative path carries neither a drive letter nor a leading `/`, so it is never rewritten in any shell form; "cd to the repository root first, then use relative paths" is the portable answer. Paths **outside** the repository (client discovery directories, product segment directories, temp directories) cannot be expressed relatively and still go through `native_path()`. The new `hf_node()` / `hf_cli()` helpers in `scripts/platform-compat.sh` make this convention explicit.
- **Official motion verification went from "zero coverage" to "actually running"**: measured, official `check --json` reports `motion.enabled=false, samples=0` when no `*.motion.json` sidecar exists — the official check closest to "watching the MP4" had **never been enabled** in this repo (not skipped: never enabled). The new `scripts/lib/motion-spec.mjs` derives an official sidecar from each frame's `data-motion-role="hero"` declaration plus the assembly timeline in `index.html`, asserting hero visibility (t ≤ 0.5s, rules §1), cross-frame ordering and subject containment. `gate.mjs check` now **fails outright** when `motion.enabled=false`, so an all-green run can never be mistaken for "motion was verified too". A frame without a hero declaration is **fail-closed** (no guessing, no skipping: a wrong guess turns the check into a constant green).
- **`check` now runs with `--json` and attributes every finding**: the official envelope carries selector / timestamp / source file / fixHint per finding, and the previous gate looked at the exit code only, throwing all of that away. New `scripts/lib/check-envelope.mjs`.
- **animation-map upgraded from "exists" to "content assertions"**: the official script computes dead zones, staggers and tween flags, but the gate only checked that the file existed and was non-empty — **every conclusion was discarded**. The new `scripts/lib/animation-map.mjs` fixes the policy: dead zones (≥1s without a tween), `degenerate` and `invisible` tweens **block**; `offscreen`, pacing flags and inconsistent staggers **warn** (which ones block is a policy decision of this repo — the official script always exits 0 and its prose documents no threshold).
- **New pixel-level audit of the finished video** (`scripts/lib/pixel-quality.mjs` + `gate.mjs quality`): the verdicts land on the **rendered pixels** — first-frame recognisability (non-background pixels ≥0.5%, ≥3 distinct colours) and "every Storyboard scene interval must contain visible change". The official motion stage counts whether an element's opacity/transform changed, not whether the picture changed; measured, the two can disagree in opposite directions (the former is diluted by "one thing in the frame is still moving", the latter is not).
- **Distribution package boundary and self-checks**: new **in-package dead-link check** (a packaged `.md` pointing at a file that does not exist inside the package aborts the build — excluded files are routinely pointed at by links, and an in-package dead link only surfaces after distribution, when fail-closed is no longer possible); `publish-skillhub.mjs` and the "standalone general-purpose tools" (MiniMax image/video scripts and their standalone docs) are excluded as a group (they are not on the production path), and the packaged `package.json` drops the npm script that pointed at an out-of-package file.
- **Package output and scratch output separated**: the package now lands in `.skillhub-pkg/pkg/`, separate from the sibling scratch area — mixed together, `install-skill.sh` installed the scratch files into the skill directory as well.
- **Full Windows support**: this repo was developed on macOS and carried POSIX/macOS-only assumptions throughout — on Windows they either crash outright, crash for inscrutable reasons, or **silently produce wrong results**. This round gathers evidence for each cross-platform defect and fixes it, and rewrites the platform declarations from "macOS / Linux" to the truth: "macOS / Linux / Windows". Full evidence, fix list, capability matrix and open items: `docs/architecture/windows-cross-platform-audit-2026-10-31.md`.
- **One official CLI entry point, resolved inside the package**: `scripts/lib/harness.mjs` gains `hfCliEntry()`, which resolves `node_modules/hyperframes/bin/hyperframes.mjs` from the `bin` field of `package.json`. The previous `node node_modules/.bin/hyperframes` is an npm-generated **sh wrapper** — running it through node raises `SyntaxError: missing ) after argument list`. `runHf` / `doctor.sh` / `bootstrap.sh` / `hf-env.sh` now all go through the real entry point; the new pure-Node `scripts/hf-version.mjs` (with `--print`) handles version checks.
- **Python interpreter is no longer hardcoded to `python3`**: on Windows, `python3` frequently resolves to the Microsoft Store `python3.exe` stub (exits non-zero, prints nothing). The new `resolve_python()` in `scripts/platform-compat.sh` tries `MINIMAX_PYTHON` → `python3` → `python` and **only accepts an interpreter that actually runs a minimal import**; `net-env.sh` and `scripts/minimax-tts.mjs` use it too.
- **Official skills are now linked by Node**: the new `scripts/lib/link-official-skills.mjs` creates a **junction** on Windows (no admin required, transparent traversal) and a symlink on POSIX. The old `ln -sfn` degrades into a full-tree copy on Windows, which breaks the link with `vendor/` — agents would then read a stale copy of the official contract, exactly the drift this repo exists to prevent.
- **New `scripts/platform-compat.sh`**: the single source of truth on the bash side — `native_path()` (`cygpath -m` for path-shape conversion toward native programs), `resolve_hf_cli()` / `hf_cli_path()` / `resolve_python()`.
- **Windows CI matrix**: new `test-windows` job (`shell: bash`, Node 22/24). Version verification now goes through `node scripts/hf-version.mjs --print` while **keeping an independent version literal assertion** — the CI-side and script-side declarations must cross-check; a single source of truth would turn the check into a tautology.
- **New `.gitattributes`** (`* text=auto eol=lf` plus binary markers): pins the line-ending strategy. CRLF breaks the `SKILL.md` frontmatter assertions and the test-case count, and makes cross-platform artifact hashes drift.
- **Product root follows the Windows Known Folder**: `defaultProductsRoot()` reads the real value of `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\User Shell Folders\Personal`, so a OneDrive-redirected "Documents" folder no longer mis-resolves.
- **New rendered-media content gate**: the new `scripts/lib/media-probe.mjs` reads three facts about a finished video into machine-checkable form (**reads only, it does not judge**): track structure (`ffprobe`), audio loudness (`volumedetect`), and black-frame intervals (`blackdetect`). Both `gate.mjs mp4` and `state.mjs set-mp4` now fail closed on them: **a video track + an audio track + non-silent audio (`mean_volume > -60 dB`) + no full-black interval lasting ≥1s**.

### Fixed
- **`fs.cpSync` silently copied nothing into a destination whose path contains non-ASCII characters** (measured in CI, **Node 22 + Windows**): after archiving a directory source package, `00-项目总控/资料包/` was **created but empty** (`原稿.md`, `证据/说明.md` both lost), while the locked-script extraction succeeded and init exited 0. Discriminating evidence: an in-process `fs.cpSync` probe with the same structure **worked**; the only difference was that the **destination path contains non-ASCII** (production targets the all-Chinese `00-项目总控/资料包`, the probe targeted a pure-ASCII name); and the very same code is **green on Node 24 + Windows / ubuntu / macOS** — only **Node 22 + Windows** is red. Root cause: without a `filter`, Node's `fs.cp` delegates the recursive copy to the **C++ fast path** `fsBinding.cpSyncCopyDir`, which on Node 22 + Windows silently copies nothing into a non-ASCII destination — no throw, no warning. Fix: `cpSync(..., { recursive: true, filter: () => true })` forces the portable JS path (`opendirSync` + per-file `copyFileSync` — both already proven to handle Chinese paths here). Regression lock: the archive case now probes **both** variants and **asserts** that the variant production uses actually copies the files, so reverting to a bare `cpSync` turns the case red on the spot instead of leaving an empty archive behind.
- **`findBash()` returned a bare command name → ENOENT once PATH was replaced** (measured in CI): the "no python3" case in `tests/net-env.test.mjs` failed with `source 失败：undefined` / `null !== 0` — which reads like "the script crashed" but actually means "it never started". Root cause: on Windows `findBash()` first tries `works("bash")` — **on this machine** the `bash` on PATH is the WSL stub (it fails), so it fell back to Git Bash's **absolute path** and was accidentally right; **on the runner** Git Bash *is* on PATH, so it returned the **bare name** `"bash"`. `spawnSync` resolves the executable name using the **child's PATH**, and that case replaces PATH with an empty sandbox to construct "no python3" — hence ENOENT. Fix: `findBash()` / `findZsh()` now always return an **absolute path** (resolved via `where`/`which`, then verified by actually running each candidate), and every `git` hit is used to back-derive Git Bash.
- **Palette confinement compared alpha → official presets were falsely flagged** (measured): the first version treated `rgba(232,93,78,0.15)` and `#E85D4E` as different colors, so the official `capsule` atmosphere component (`FRAME.md:107-109` states "1–3 radial candy glows (6–15% opacity)") and its shadow token were **both flagged as out-of-palette** — the gate became a false positive against the official preset itself. Now compared **by RGB, ignoring alpha**: an opacity change is the same brand color under a different alpha, not a second color; alpha-related concerns belong to the official `check` WCAG contrast stage.
- **The chrome exemption matched only px values → a 14px body label slipped through** (measured): the first version exempted any font size whose value appeared among the frame.md px tokens, so the official `capsule` `label: px 14` let a worker's hand-written **14px body label** pass (a 30px→14px mutation unexpectedly PASSed). Now a **double condition**: the token name must hit chrome semantics (counter / pagenum / rail / colophon / credit / footnote / meta / chrome) **and** must not hit carrying semantics (label / tag / kicker / caption / badge / overline / attribution / body / title / headline) — carrying tokens win, because under-exempting a chrome token is safer than over-exempting a 14px label.
- **`doctor.sh` discarded the official doctor's entire verdict under a login shell** (measured): the script handed an MSYS POSIX **absolute** path to native node. A login shell presets `MSYS_NO_PATHCONV=1`, which switches that conversion off — so `/d/foo` arrived verbatim, node resolved it to `<current drive>\d\foo`, and the run died with `MODULE_NOT_FOUND`. The consequence is not an error message but **the loss of every official doctor conclusion**, reported as "required items not passing" (a false negative that sends the investigation in the wrong direction). A non-login shell works, so testing only with `bash -c` can never catch it. Now relative paths + the `hf_node()` helper.
- **`install-skill.sh` aborted outright under a login shell** (measured): same root cause, and that script **never sourced `platform-compat.sh` at all** → `MODULE_NOT_FOUND` plus `set -e` abort under a login shell, so the skill could not be installed at all.
- **`bootstrap.sh` split the vendor hash on whitespace**: `find … | xargs $hasher` splits on spaces in file names, reports `No such file or directory`, and under `set -euo pipefail` **aborts silently** (exit 123, no error message). Now `-print0 | sort -z | read -d ''` handles each entry individually (new `scripts/lib/tree-hash.sh`, directly callable from tests). Also corrected: the aggregate hash used to fold **absolute paths** into the content, i.e. it was a "path + content" hash — the same tree moved to another drive letter would read as "drifted".
- **The packaging manifest was packed into the package → self-referential growth**: `.skillhub-pkg.manifest.json` was written to the **same level as** the package directory (repository root), so it was in neither the content exclusion list nor `.gitignore` → the second build packed it in and the package grew for no reason, and a build near the size limit would fail closed. Now excluded and ignored.
- **`state.mjs set-mp4` failed open on duration validation**: a full-text regex for `- duration:` scanned the STORYBOARD — it only recognised half-width colons (a full-width `duration：4s` yields zero durations → `expected=0` → **the entire duration check was silently skipped**, so a bad video could still be bound), and it scanned the whole text (one extra `- duration: 30s` outside a frame block inflates the expected total → **a correct MP4 gets rejected**). Now a structured parse (the same `storyboardDurationFacts` the gate uses), and "there is a duration line but no number parses out" changed from a silent skip to an explicit failure.
- **`install-skill.sh` deleted the bootstrap artefacts on reinstall**: the old implementation did `rm -rf "$DEST"`, taking `node_modules/` (dependencies) and `vendor/` (the official skills fetched at the locked commit) with it — a reinstall meant re-downloading dependencies and official skills. Now an **in-place sync**: package files overwritten, stale package-external files removed, `node_modules` / `vendor` kept in place. That also dodges a Windows trap: a directory whose handle is held by a running process **cannot be renamed** (`MoveFileEx` → `ERROR_ACCESS_DENIED`) — measured, moving the whole installed skill directory fails, while copying the same content elsewhere and then moving succeeds; it is the *occupied old tree* that fails, not the content.
- **The `test-windows` job in `ci.yml` was red on its first step**: the comment claimed "windows-latest ships ffmpeg", but the official `actions/runner-images` Windows2025 image tool list has **no ffmpeg** (only ImageMagick / jq / zstd). Now `choco install ffmpeg`; `makeTinyMp4` also got an ffmpeg-missing guard (the previous failure message was "null !== 0", which hides the root cause).
- **The Python interpreter variable name was split across two worlds**: the bash side read `HARNESS_PYTHON`, the Node side and the docs read `MINIMAX_PYTHON` → setting `MINIMAX_PYTHON` as documented made the bash side fail to resolve → the proxy was silently cleared and doctor raised false warnings, while TTS kept working. Now `MINIMAX_PYTHON` is authoritative and `HARNESS_PYTHON` is kept as a legacy alias.
- **Two capabilities shared the number `#7`** in §3 of the rules (`final delivery` and `keyframes` diagnostics), and the three tables totalled 13 rows while being called 12 items; README/SKILL still said "only 3 of 12 items land in §3.1" (not updated after `e9cb611` added `final delivery`). Now renumbered **1–13** in reading order, and all three documents say "**4 of 13** land in §3.1".
- **`references/faq.md` contradicted itself, and the issue templates copied the wrong advice**: one passage says "**do not** use `node node_modules/.bin/hyperframes`" (measured: that is an npm-generated sh wrapper — running it through node raises `SyntaxError`), while another passage's "correct approach" recommends exactly that; both issue templates recommended it too. Now uniformly `node scripts/hf-version.mjs --print`.
- **The contract in `references/commands.md` did not match the code**: it promised `[state]` / `[new-video]` prefixes that the code never uses, and said "exit 1 on failure" while there are 6 places with `exit 2` (usage error). Rewritten to the actual behaviour.
- **The artefact count in `doctor.sh`'s message was wrong**: the comment said "10 items", but `HF_REQUIRED_ARTIFACTS` in `bootstrap.sh` lists 13. Corrected.
- **`gate verify` falsely reported "STORYBOARD frame order/duration drift"** — a **platform-independent** defect surfaced by the Windows end-to-end run, blocking production on every platform: the injection binding stores the per-frame parsed `meta.duration` (the string `"undefined"` when a frame has no `- duration:` line), while the gate counted `- duration:` lines with a regex over the raw text (an empty array when the lines are absent). The two representations can never agree when the lines are missing, so **an undrifted artifact was judged as drifted**. Official `sync-durations` only **updates** existing duration lines and never adds them, so "a frame without a duration line" is a legitimate official shape. The gate now compares "frame number + duration" using the **same parser as the injection** — no less information than before — and drift detection still rests on `storyboard_sha256`. A regression test pins it (mutation-verified: it goes red the moment the fix is reverted).
- **Proxy probing always concluded "unreachable" on Windows, silently connecting direct**: the probe used `python3` and therefore hit the Store stub, so "this machine has a proxy" was misread as "no proxy" and traffic went out unproxied. With the real interpreter from `resolve_python()`, probing is correct.
- **Python stdout is GBK (cp936) under Windows pipes**: Node decoded it as utf8 and got mojibake; with emoji or supplementary-plane characters in the script, Python hard-crashed with `UnicodeEncodeError`. The three minimax scripts now force UTF-8 output, and `minimax-tts.mjs` injects `PYTHONIOENCODING=utf-8` / `PYTHONUTF8=1`.
- **Python artifacts did not pin LF**, so hashes differed across platforms. `write_json_file()` now writes bytes with LF.
- **`renameSync` over a read-only target fails with EPERM on Windows** (POSIX `rename()` has no such rule): the new `replaceFileSync()` clears the read-only attribute and retries **only** on `EPERM`/`EACCES`; every other error code is rethrown untouched.
- **`captions-zh.mjs` detected "is main module" case-sensitively**: on Windows the casing/separators of `import.meta.url` and `process.argv[1]` differ, so the script would **silently exit 0** — looking successful while doing nothing. It now compares both sides via `realpathSync`.
- **Cross-drive path guard missed cases**: `relative()` returns an absolute path across drives and the guard read it as an escape; `isAbsolute(rel)` was added.
- **A missing `ffprobe` was disguised as a code bug**: when the external command does not exist, `spawnSync` returns `stdout=undefined` and calling `.trim()` throws a `TypeError`. This is now consolidated into `probeDurationSeconds()`, which returns `{ok, seconds|reason}` and names the actual cause ("ffprobe is not installed / not on PATH").
- **`tests/net-env.test.mjs` hardcoded `/bin/bash` and `/bin/zsh`**, and the "no python3" case was **permanently skipped** because `symlinkSync` was never called (a silent, hidden failure). ## [0.2.7] — 2026-10-25

Final-delivery and future-production hardening: master close now delivers a byte-identical `99-最终合成/renders/final.mp4`; caption balancing cuts on Chinese word boundaries; harness identity is recorded in state; preflight includes frame-check.

### Added
- **`gate.mjs render-ready` — artifact check at render time** (hit in production; until now this was discipline only, with no machine gate). `preflight` runs **once, at authorization time**, while rendering happens **after** it. Any rewrite in between — the official Studio preview rewrites `compositions/captions.html` and `index.html` while it runs — means the bytes being rendered are not the bytes that were validated, and nothing checked it. `render-ready` re-reads the final-look receipt and recomputes every artifact on disk, comparing **every byte the renderer actually reads**: the frame set, `index.html`, captions, audio metadata, plus the four asset directories `assets/voice/`, `assets/fonts/`, `assets/bgm/`, `assets/sfx/` — none of these appear in any per-file binding, so they were entirely outside the gate's view (swapping a wav, editing a font, or replacing the music track was undetectable). Any drift fails closed and prints the exact repair commands. Zero side effects, pure hash re-check.
- Receipt bumped to **v3**: binds **four** asset directories the renderer actually reads — `assets/voice/`, `assets/fonts/`, `assets/bgm/`, `assets/sfx/` (the official `assemble-index.mjs` writes BGM and sound effects into the media table in `index.html`; swapping one was completely silent). Directory digests also moved from an **extension whitelist** to "include everything except OS noise such as `.DS_Store` / `Thumbs.db`" — a whitelist misses unknown extensions (`.ogg`, `.aiff`, …) that the renderer may well read; that is a detection gap, not robustness. v1 / v2 receipts are explicitly rejected by `render-ready` with an instruction to re-run preflight — that is the truth, not a malfunction.

### Changed
- **`state.mjs set-mp4` now requires `gate render-ready` to pass**: binding is the first machine check after rendering, so **a drifted render can no longer enter the master chain**. It also now requires a valid **final-look approval** for the segment (previously a bare start approval was enough to bind any MP4) — the official order is "final-look approval → render → set-mp4", and without that link there is no way to say *which* render was authorized.
- `docs/rules/production-workflow-rules.md` gains §3.4 "render input integrity": Studio preview must be stopped before rendering, and afterwards captions → assembly → transitions → preflight → re-approval → render → `set-mp4` must be re-run.
- `docs/rules/production-workflow-rules.md` §4 dispatch discipline gains three rules: **the orchestrator must review a worker's implementation against the cross-frame continuity spec, not just trust its report**; **a spec shared across frames must be written as a single authoritative value and must not carry two contradictory forms** (a measured incident: `border: 0.4cqw solid` sat next to the parenthetical "4px ink stroke", but `0.4cqw` is 7.68px on a 1920px canvas — one instrument ended up with both a 4px and a 7.68px stroke; a self-contradictory spec hands the choice to the implementer); **a scaled-down copy is not the same object** (a prop moved elsewhere at reduced size must scale its geometry by the same factor, or viewers will not recognize it as the same prop and the "same meter → same reading" argument collapses). Lint and check can only prove that a frame is self-consistent, not that it says the same thing as the frames around it — gauge baselines, angle conventions, and reading chains are exactly where a claim gets inverted, and no machine gate can see them. The dispatch context must pin the cross-frame spec; the orchestrator checks every frame against it.

### Fixed
- **`render-ready` no longer mistakes "did not exist in the first place" for drift** (found by a zero-trust self-review): a directory binding is recorded as `null` when the directory did not exist at preflight time, and the re-check treated every `null` as drift — so a perfectly legitimate segment that uses only system fonts and has no `assets/fonts/` would be permanently blocked and could never pass `set-mp4`. The semantics are now: **absent at preflight ⇒ must still be absent**; only a directory/file that *appears* out of nowhere counts as drift (that would mean the render reads bytes nobody verified). A regression case pins it (mutation-verified: removing the fix turns the case red on the spot).
- **The official CLI's browser download cache (`chrome/`) no longer pollutes the worktree or the published package**: `hyperframes browser ensure` writes its Chrome download cache to `<cwd>/chrome/`. Running it once at the repository root leaves a hundred-megabyte archive behind — it was in neither `.gitignore` (one `git add -A` would commit the binary) nor the path-based package exclusions (it was excluded only incidentally by the extension whitelist). It is now excluded by path (`build-skill-package.mjs` `EXCLUDE_DIRS`) and added to `.gitignore`.

### Final delivery
- `state.mjs master --kind close` now writes `99-最终合成/renders/final.mp4` and `final-render.json`, binding final/candidate hashes, duration, and harness identity in `state.master.final_render`. The final is a byte-identical copy of the candidate, never a re-encode.
- New `gate.mjs final-delivery`: verifies final exists, matches the candidate SHA-256 exactly, has the same duration, and has a complete manifest; missing final or drift fails closed.
- `new-video.mjs init` creates `99-最终合成/renders/` and records harness version/commit/dirty in `state.harness`; a dirty worktree is called out explicitly so production versions remain attributable.
- `captions-zh` balanced splitting now cuts on Chinese word boundaries and protects quotes / em dashes / function words; regression tests were added.
- `gate preflight` now passes `--frame-check` to the official check, bringing project-level safe boundaries into preflight.

  - `scripts/bootstrap.sh` no longer uses `hyperframes skills update` — that command hardcodes "latest" as upstream main's **live HEAD**, so it cannot be pinned to the commit this repo declares, and it "removes any no longer published" skills. It now fetches the official `skills/` tree at the pinned SHA into `vendor/skills/` via git: an outer loop over transports (HTTPS / SSH) and an inner loop over ref forms (by SHA / by tag), trying all four combinations, and every successful fetch is immediately verified with `git rev-parse FETCH_HEAD` to confirm it is the pinned commit; `--filter=blob:none` makes the fetch take only commit and trees, pulling blobs on demand at checkout, so the transfer excludes the whole-repository content this repo does not need. It then fail-closed checks the 10 official artifacts this repo actually references; a missing one is an error, never a silent skip.

## [0.1.0] — 2026-10-08

First public release.

### Added
- **Management-layer positioning**: preserve the flow (rules and gates), fill the gaps (locked-script segmentation / MiniMax word-level timing injection / master concatenation / state and approvals), upgrade capabilities (mandatory wiring of official quality capabilities).
- **Official capability audit** (`docs/architecture/hf-0.8.36-capability-audit.md`): confirmed that HF 0.8.36 natively adopted a "single agent + one sub-agent per frame" model; the previously self-built worker execution layer, transport evidence, three-slot queue, and heartbeat/lease were all retired.
- **Production scripts** (single-step, idempotent, deterministic, agent-call-free): project scaffolding, MiniMax TTS injection, Chinese caption grouping, gates, state and approvals, master concatenation.
- **Rule documentation** (each a single owner): production workflow, visual rulebook, caption contract, locked script and segmentation.
- **Offline capability floor**: the official escape hatch `HYPERFRAMES_SKIP_SKILLS=1` blocks the segment scaffolding's hidden network dependency; `npm test` runs fully offline, including a black-hole-proxy case for that offline floor.
- **Single-point network policy** (`scripts/net-env.sh`): npm mirror in mainland China; GitHub/npm proxy **probes `127.0.0.1:7890` by default and only enables it when reachable**; MiniMax is exempted for direct connection.
- **Evidence integrity**: SHA-256 chained binding of locked script → TTS → injection binding → MP4; a frame's voiceover must be fully equal to the locked script after normalization.
- **Gates**: `verify` / `authorized` / `final-look` / `check` (a thin wrapper around official `--strict`) / `mp4` / `next-segment` / `master-inputs` / `layout-guard`.
- **Generalized locked-script markers**: `<any-namespace>:script:start|end`, backward compatible with existing material packages.
- **CI**: ubuntu + macos × Node 22/24.

### Security
- API keys come only from environment variables or the macOS Keychain; they never enter the repository or the logs.
- The injection binding schema is versioned; historical formats **refuse back-filled hashes that would forge evidence** and can only be re-derived.
- Secret and personal-identifier scan: the full history contains no secrets and no personal absolute paths.
